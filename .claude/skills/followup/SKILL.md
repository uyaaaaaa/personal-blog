# PR の見届け

**出したセッションが最後まで見る。** 出したら、購読・セッション名・レビューを**同じターンで**済ませてから CI に戻る。

- **PR のイベント（CI・レビュー・コメント）を購読する**
- **セッション名を `PR #N` に変える。** 一覧からどの PR を見ているセッションか辿れるようにする
- **レビューのエージェントを起こし、返ってきた JSON を出す。** 起こし方と出し方は `review`。**渡すのは PR 番号だけ。書いた側が自分の差分を見ても、直したい形が先に見えていて判定にならない**ので、実装の意図やどう見てほしいかは渡さない

## CI とレビューに追従する

| 来たもの | どうする |
| :--- | :--- |
| CI の赤、lint、自明な不具合 | 直して push。理由は PR に1行 |
| レビューの指摘 | `address` に従う |
| コンフリクト | `main` をマージして解消 |

- **判定が `Approve` になるまで、直して push するたびにエージェントを起こし直す。** 前回の指摘は渡さない
- **往復は3回まで。** 3回目で残った論点は直さず、PR に1コメントでまとめて書き手に渡す

## 終わり

- **受けた指摘を台帳に書き留める。** `node scripts/harness-journal.mjs append <PR番号>` に、指摘の要旨と直し方を標準入力で渡す。**指摘が0件なら書かない**（→ `codify`）
- **判定・CI・実測を報告して終える**

## 見届けられないとき

購読の手段が無いか、セッションが続かないなら**待たない。** そのときの CI とレビューの状態を報告して終える。
**「後で確認します」と書かない。** 見ないものを見ると書くと、誰も見ていない PR が残る。
