# issue の拾い方

**選んで起こすところまで。** 1 issue の進め方は `assign` が持つ。

**迷ったら落とす。** 拾い損ねても次の回で拾える。間違って拾うと、要らない PR が1本残る。

## 1. 数える

未マージの PR がラベルを問わず**5本以上あれば、この回は1本も拾わない。** レビューとマージは書き手が持つので、PR が溜まると詰まる。

## 2. 落とす

open issue を上から順に落とす。

| 落とす | なぜ |
| :--- | :--- |
| `needs-decision` ラベル | 書き手の判断待ち。本文は読まない |
| `documentation` ラベル | 記事のネタで、`article` の対象 |
| `## ゴール` `## 現状` `## 完了条件` が揃っていない | 完了条件が外から判定できることが自走の前提（→ `create-issues`） |
| 完了条件が4つ以上 | issue が2本に割れている |
| `claude/issue-<番号>-` の remote branch があるか、`Closes #<番号>` の open PR がある | 既に走っている |
| 完了条件が外から判定できない | 「使いやすくなっている」は条件ではない |
| 完了条件が判断を含む | 「〜が決まっている」は、決めるのが書き手の仕事で、直す作業ではない |
| `.claude/rules/docs.md` の ADR 基準を両方満たす判断を要求する | 既存の ADR を差し替えるものも同じ |

**判断で落としたら `needs-decision` を付ける。** 形式で落ちたものには付けない。直せば済む話で、書き手の判断待ちではない。

**assignee は見ない。** このリポジトリでは「着手中」の意味で使われていない。

**取り残しは拾い直す。** branch はあるが open PR が無く、最終コミットが6時間より古いなら落とさない。報告に1行書く。接尾辞が変わるので衝突しない。

## 3. 並べる

`bug` を先、`enhancement` を後。同じなら作成が古い順。放置され続ける issue を作らない。

## 4. 起こす

先頭から**最大2本**。1 issue につき**兄弟セッションを1つ**（`create_session`）。

**サブエージェント（`Agent` ツール）にしない。** dispatch 自身が使い捨てのコンテナで動くため、このセッションの終了に道連れで止まる。

| 指定するもの | 値 |
| :--- | :--- |
| `model` | `claude-opus-5`。**省略しない。** 省くと発火元の Routine のモデルを継ぐ |
| `source_url` | `https://github.com/uyaaaaaa/personal-blog`。プロンプトに URL を書くだけでは、起きたセッションから GitHub に投稿できない |
| `title` | `issue #<番号>` |
| `prompt` | `assign` に従って `#<番号>` を進めること／作業ブランチは `claude/issue-<番号>-<英数字4〜6>`（次の回の重複判定がこれを見る）にすること／答えを待てる相手がいないこと。これだけ |

**実装の方針を渡さない。** issue の読み方は `assign` が持っている。

**起こしたら待たない。** 完了を待機・ポーリングしない。

## 5. 報告

Slack の `#blog-agent`（`C0BV67WD6Q5`）に、1回の発火につき最大1つ。書くのは、起こした issue の番号とタイトル／前回から変わった PR（出た・緑になった・赤いまま見る者がいない）／取り残しを拾い直したこと／PR が5本以上で拾わなかったこと。

**どれも無ければ投稿しない。** 毎時の「なし」を残さない。

**出す前にチャンネルの直近を読み、同じことを書くならやめる。** 状態を持たずに重複を防ぐ。
