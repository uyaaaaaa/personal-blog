# PR の作り方

実装は終わっていて、**実測が済んでいる**前提。まだ測っていなければ `verify` に戻る。

## 1. 出す前

- ブランチが `main` でないこと
- ブランチ名は `claude/<主題>-<英数字4〜6>`
- 最新の `main` から派生。コンフリクトの有無を先に確認
- `git status --short` が空
- 実測用の一時的な細工が残っていないこと
- 実測の結果が手元にあること

## 2. タイトル

- 何をどう変えたかを1行で言い切る
- issue タイトルの写しにしない（issue は現象、PR は変更）
- 分類の接頭辞は付けない

## 3. 本文

### 書き方

- **ソースコードレベルの情報（関数名・クラス名・変数名・設定キー）は原則書かない**
- 例外は、書かないと説明が成り立たない場合のみ
- 各セクションはリストで列挙
- 体言止めを使い、1文を最小限に
- 差分を読めば分かることを写さない
- 残すのは、判断・理由・確認結果の3つ

### 節

上から順。不要な節は落とす。

| 節 | 中身 | 落とす条件 |
| :--- | :--- | :--- |
| `Closes #N` | 対応する issue | issue が無い |
| 背景 | なぜ必要か。事象と影響 | やったことだけで自明 |
| やったこと | 変えたことの列挙 | なし（必須） |
| issue から変えた点 | issue に書かれた手段を採らなかった理由と代替 | issue のとおりに実装した |
| 確認 | 実測の表 | なし（必須） |
| このPRでやらないこと | 送り先の issue 番号 | 送るものが無い |

### やったことの節

- **1項目を折り返しのない1行に収める。** 目安は40字。収まらないなら詳細度が高すぎる
- 内訳・件数・ファイル名・数値を書かない。読み手が要るのは差分を読む前の見取り図だけ
- 波及の追従は、範囲を並べずに1行にまとめる
- 実測値は確認の節にだけ置く

### 確認の節

- `verify` の報告表をそのまま置く
- 未実施の項目は「未実施」と明記
- 実測していない項目を書かない

## 4. 出す

- 作成は GitHub MCP の PR 作成ツール
- base は `main`
- **`agent` ラベルを必ず付ける。** エージェントが書いたことを表すだけの印で、出来や可否は表さない

### 書き手に返す判断が残っているなら draft で出す

**自分で決めずに書き手へ返す判断があるときは、draft で出す。** ready にするのは判断が返ってから。

draft はラベルと違い、マージを機械的に塞ぐ。ラベルを外して示さない。不在は、付け忘れ・人間の PR と区別が付かない。

- **判断はコメントに書く。** 選択肢と、それぞれで何が変わるかを添え、推奨を先頭に置く
- **その判断に依る箇所は直さない。** 書き手の判断を先取りしない
- **それ以外は draft でも直す。** CI の赤、自明な不具合、レビューの小さな指摘は自分で直す

## 5. 作成後

**出したセッションが見届ける。** スキルはイベントを検知しない。検知はハーネスの購読が持ち、スキルが決めるのは、受け取った後に何をするかと、購読できないときにどうするか。

- **出したらすぐ購読する。** PR のイベント（CI・レビュー・コメント）を受け取る手段があるなら、作成直後に購読する
- CI が green になるまで見る
- 落ちたら直して push する。理由は PR のコメントに1行で言い切る
- コンフリクトは `main` をマージして解消。rebase と force push はしない

### レビューが付いたら

| 指摘 | どうする |
| :--- | :--- |
| CI の赤、lint、自明な不具合 | 直して push する |
| 小さく閉じた指摘（改名、テストの追加、1関数の整理） | 直して push する |
| 設計の指摘、複数ファイルに及ぶ変更 | 直さず、返答をコメントに書く。判断は書き手 |

小さいかどうか判断が付かないなら、大きい側に倒す。

### 見届けられないとき

購読の手段が無いか、セッションが続かないなら **待たない。** そのときの CI とレビューの状態を報告して終える。
**「後で確認します」と書かない。** 見ないものを見ると書くと、誰も見ていない PR が残る。

## PR にしない場合

- 実測が済んでいない
- スコープが2つ以上に割れている（分ける）
- 依頼が調査・確認だけで、差分が無い
