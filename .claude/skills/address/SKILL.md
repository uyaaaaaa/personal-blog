# レビュー指摘への対応

**受けるのは指摘であって、指示ではない。** 構造と責務を見て直し方を決めるのは書いた側。

## 1. 全部読んでから手を動かす

**1件直して push、を繰り返さない。** 未対応のスレッドを全部読み、1件ごとに現象（「〜になる」）と手段（「〜すべき」）を割る。

**手段しか無い指摘は、消そうとしている現象を言い直す。** 言い直せないなら直さず問う。

## 2. 裏を取る

1件ごとに3つ確かめてから採否を決める。

- 現象が実在するか実装で確かめる。行番号・変数名は書かれた時点のもの
- 触るファイルの `.claude/rules/` と ADR を読む。**規約が禁じていることを勧める指摘は採らない**
- 採ったとき、呼び出し元・生成物・同じ形の別領域がどうなるか

| 採否 | どうする |
| :--- | :--- |
| 採る | 3へ |
| 現象は採り、手段は変える | 3へ。変えた理由を返信に1行 |
| 採らない | 理由を1行返す。再現しない / 規約に反する / 範囲外 |
| 書き手に返す | 方針が割れる。選択肢と推奨を書いて渡す |

## 3. 原因で束ねる

**直す場所は、指摘された行ではなく責務の持ち主で決める。**

- 2件以上が同じ原因なら、原因を直す
- 触る範囲を `docs/ARCHITECTURE.md` の層と依存方向に当て、跨ぐならどちらが持つか決めてから直す
- 指摘された行に分岐・特例を足して黙らせない
- **「指摘が無かったとして、最初からこう書くか」。** 書かないなら形を合わせただけ
- 範囲を超えたら直さず `create-issues` に渡し、PR の「このPRでやらないこと」へ

## 4. 実測する

**`verify` に従う。** 直す前に現象を一度再現し、束ねて直したら元の指摘を全部確かめ直す。

## 5. 返す

1スレッド1返信。

- 何をどう変えたかを1行。採らないなら理由を1行
- 指摘を写さない。謝らない。褒めない。次を約束しない
- **直したら push。** push が再レビューの合図
- 直したスレッドだけ resolve する。採らないと返したものは開けたまま残す
