# レビューの手順

指摘の探索・選別・グレード付けはエージェント `review` がやる。**PR のレビューは `Review` ワークフローが PR を開いたときと push のたびに起こし、投稿まで持つ。**

## PR

- 起こし直すときは `Review` ワークフローを PR 番号だけ渡して手動で走らせる。自分で Agent を起こして投稿しない
- **判定を本文に書いた通常コメントで代えない。** それはレビューではないので、Approve も Request changes も付かない
- 走らせたら `review.yml` の最新の run が `success` か見る。失敗したまま報告しない
- **レビューが5回付いた PR は、もう起こされない。** 残った論点を1コメントにまとめて人に渡す

## 作業ツリー（PR が無い）

`Agent(subagent_type: "review")` に `main からの差分をレビューする` とだけ渡す。

- **実装の意図・見どころ・直した点は渡さない。** 直したい形が先に見えていると判定にならない
- lint と test は自分で通してから渡す
- 返ってきた形のまま会話に返す。投稿しない

**判定と件数だけを報告して終わり。** マージはしない。
