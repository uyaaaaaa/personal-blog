# UI 変更の手順

## 1. 読む

実装が正なので、まず触るコンポーネントの `.vue` を読む。個々の指定の理由は文書に無いので、**一見不要に見える指定は、消して lint / build / 目視で確かめる**（→ §3）。

方針に触れる変更（トークン、レイアウトの原則、本文の見た目、機能の要件）は、先に `docs/DESIGN_GUIDELINE.md` の該当節を読む。

## 2. 実装する

既存の同種コンポーネントの書き方に揃える。Tailwind のクラスを基本にし、複雑な状態やアニメーションだけ scoped CSS にする。

DESIGN_GUIDELINE の方針を覆したら、同じ変更でそちらを直す。覆した方針が ADR の基準（`.claude/rules/docs.md`）に当たるなら `docs/adr/` に1ファイル足し、`docs/DECISIONS.md` にも行を足す。

## 3. 実測する

**`verify` スキルに従う。** UI そのものは測らないと分からないので、**目視まで必ず行く。** 読んで判断したものは未確認として扱い、測っていないものを「確認した」と書かない。
