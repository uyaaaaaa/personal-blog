# UI 変更の手順

## 1. 読む

実装が正なので、まず触るコンポーネントの `.vue` を読む。個々の指定の理由は文書に無いので、**一見不要に見える指定は、消して lint / build / 目視で確かめる**（→ §3）。

デザインの判断に迷ったら `docs/DESIGN_GUIDELINE.md` を読む。持っているのは原則だけで、値と構造は実装が正。

## 2. 実装する

既存の同種コンポーネントの書き方に揃える。Tailwind のクラスを基本にし、複雑な状態やアニメーションだけ scoped CSS にする。

DESIGN_GUIDELINE の原則を覆したら、同じ変更でそちらを直す。覆した方針が ADR の基準（`.claude/rules/docs.md`）に当たるなら `docs/adr/` に1ファイル足し、`docs/DECISIONS.md` にも行を足す。

## 3. 実測する

**`verify` スキルに従う。** UI そのものは測らないと分からないので、**撮って自分で見るところまで必ず行く。** 読んで判断したものも、証跡の無いものも未確認として扱う。

**撮った画面は会話にも渡す。** `before-` があれば並べる。
