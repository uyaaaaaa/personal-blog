# issue の作り方

**対象は番号の無い課題の持ち込みだけ。** 番号のある依頼は `assign`、PR は `pr`。

目的はひとつ。**対応する人が手段を自分で選べる issue にすること。**
だから issue の主役は**完了条件**で、解決手段ではない。手段を書き込むほど、対応する人の思考はそこに寄る。

## 全体

| フェーズ | やること | 終了条件 |
| :--- | :--- | :--- |
| 1. 聞く | 課題感を深掘りする | ゴールが1文で言える |
| 2. 裏を取る | 書く事実を実装で確かめる | 現状が観測した事実だけになった |
| 3. 詰める | 完了条件を決める | 手段に依存せず、判定が割れない条件になった |
| 4. 出す | 本文を提示して発行する | 承認を得て発行し、番号を報告した |

**1と3を飛ばさない。** 持ち込まれた課題感は、たいてい症状か手段のどちらかの形で来る。そのまま書くと、ゴールの無い issue になる。

---

## 1. 聞く

**聞く前に取れる事実は取る。** 該当ファイル、`docs/DECISIONS.md` の索引、同じ課題の既存 issue（重複は検索して確かめる）。調べた結果は質問と一緒に短く出す。

質問は `AskUserQuestion` で。**答えを聞かないと立てられない質問を、同じラウンドに混ぜない。**

**ラウンド1 — 前提なしで答えられる**

| # | 聞くこと | なぜ効くか |
| :--- | :--- | :--- |
| 1 | **どうなってほしいか。** 1文で言い切ると? | ゴールが決まらないと完了条件が書けない |
| 2 | **いま何が起きているか。** いつ・どこで気づいたか | 再現しない課題は、直ったことも確認できない |
| 3 | **放っておくと何が困るか** | 優先度と、そもそも issue にするかが決まる |

**ラウンド2 — ラウンド1が決まって初めて聞ける**

| # | 聞くこと |
| :--- | :--- |
| 4 | **何を見れば「終わった」と分かるか** |
| 5 | **今回やらないこと。** 一緒に見つけた別の問題を含めるか |
| 6 | **触ってほしくないもの。** 既にある判断と衝突しないか |

## 2. 裏を取る

**issue に書く事実は、書く前に実装で確かめる。**

- 行番号・変数名・ファイル名を書くなら、開いて今の状態を見る
- 再現を試す。再現しないなら、条件が揃っていないだけのことがある。**条件を現状に書く**
- 確かめられなかったことは「推測」と1語で明示するか、書かない

## 3. 詰める

### 節

上から順。任意の節は、書くことが無ければ落とす。

| 節 | 中身 | 必須 |
| :--- | :--- | :--- |
| ゴール | 何がどうなってほしいか。1〜2文の言い切り | 必須 |
| 現状 | 観測できる事実だけ。再現手順・出力・該当箇所 | 必須 |
| 完了条件 | チェックリスト。満たしたかを外から判定できる状態 | 必須 |
| 前提・制約 | 触らないもの、既にある判断へのリンク | 任意 |
| 手がかり | 読む場所と、分かっている事実。**指示ではないと明記** | 任意 |
| 範囲外 | 今回やらないこと。送り先の issue 番号 | 任意 |

### 完了条件

- **手段を含めない。** ✗「フォールバックを入れる」 → ○「日本語だけのタグでも、その一覧に他のタグの記事が混ざらない」
- **誰が見ても判定が同じになる形にする。** 「使いやすくなっている」は条件ではない
- **3つまで。** 4つ以上になったら、issue が2本に割れている（→ 分ける。親子にしてよい）

### 書かない

- 実装案、編集の手順、使うライブラリや API の名前
- 「手がかり」に書いてよいのは、**読む場所と観測した事実**だけ。案を書くなら、採らなくてよいと明記する
- 差分や実装を読めば分かることの写し

### 分量

**本文40行以内、1節5項目以内、1項目1行。** リストと体言止めで書き、言い切る。

## 4. 出す

- タイトルは**1行の言い切り**。分類の接頭辞は付けない
- ラベルは `bug` / `enhancement` / `documentation` から1つ
- **発行前に本文を全文出して承認を取る**
- 発行は GitHub MCP の issue 作成ツール（`gh` は使えない）
- 発行したら番号と URL を報告する。複数に割ったら、その関係も

**対応はこのスキルの範囲外。** 着手は `assign` に渡る。
