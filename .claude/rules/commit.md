# コミットのルール

**件名には「何を」と「どう変えたか」の両方を書く。** 片方だけだと、差分を開くまで何が起きたか分からない。

| 書く | 書かない |
| :--- | :--- |
| `View Allの判定をその幅で実際に見えている件数に合わせる` | `View Allを修正`（どう変えたかが無い） |
| `ページングの判定を utils の純粋関数に出してテストで守る` | `リファクタリング`（何を・どう、の両方が無い） |

- ファイル名・件数・数値は書かない。差分が持っている
- issue の文面を写さない。issue は現象、コミットは変更
- 本文は任意で、書くのは「なぜ」だけ。「何を」は件名と差分が持つ

## 1コミットの範囲

- ドキュメントの更新は実装と同じコミットに入れる。切り離すと理由が失われる
- 整形だけのコミットは分け、ハッシュを `.git-blame-ignore-revs` に足す
- 実測用の一時的な細工は含めない（→ `verify` スキル）
