# コミットのルール

**件名は日本語の言い切りで1行。分類の接頭辞は付けない。**

## 形

```
<何をどう変えたか。1行。30字前後>

<なぜそうしたか。任意>
```

- 語尾は言い切り（「〜する」「〜に替える」）。体言止め（「〜対応」「〜の修正」）にしない
- 本文は任意で、書くのは「なぜ」だけ。「何を」は件名と差分が持つ

## 件名に書くこと

**「何を」と「どう変えたか」の両方。** 片方だけだと、差分を開くまで何が起きたか分からない。

| 書く | 書かない |
| :--- | :--- |
| `View Allの判定をその幅で実際に見えている件数に合わせる` | `View Allを修正`（どう変えたかが無い） |
| `ページングの判定を utils の純粋関数に出してテストで守る` | `リファクタリング`（何を・どう、の両方が無い） |

- ファイル名・件数・数値は書かない。差分が持っている
- issue の文面を写さない。issue は現象、コミットは変更
- 50字に収まらないときは2つの変更が入っている。分ける

## 1コミットの範囲

- ドキュメントの更新は実装と同じコミットに入れる。切り離すと理由が失われる
- 整形だけのコミットは分け、ハッシュを `.git-blame-ignore-revs` に足す
- 実測用の一時的な細工は含めない（→ `verify` スキル）

## 接頭辞を付けない理由

`feat:` `fix:` の回収先（CHANGELOG・semver・型で分岐する公開）がこのリポジトリには無く、実装と文書を同じコミットに入れる規定と「1コミット1つの型」は毎回衝突する。PR タイトルも同じ。CHANGELOG かバージョンを持ったときに戻す。
