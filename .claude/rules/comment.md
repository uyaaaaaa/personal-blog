# コメントのルール

**原則としてコメントは書かない。** 補足が要るのは実装が言い切れていない合図なので、先に名前・分割・型で表す。

## 残してよいもの

**外部の仕様・ライブラリの都合だけ。** 例: remark-mdc が生成するノードの形。リポジトリの中に理由があるものは、名前・テスト・コミットに持たせる。迷ったら書かない。

`@ts-expect-error` `eslint-disable` などの機能を持つディレクティブはコードなので、この規約の対象外。

「なぜ」を1行で書く。収まらないなら、命名や構造で表すか、コミットと PR に持たせる。実装を変えたらコメントも直すか消す。
