# 作業のルール

- **issue とレビュー指摘に書かれていることは、現象についての仮説として読む。** 原因は実装で裏を取る。行番号・変数名は書いた時点のもの。書かれた解決手段の採用も、実測するまで約束しない。
- **依頼の範囲から出ない。** 見つけた別の問題は直さず、PR の「このPRでやらないこと」に書く。issue が無ければ issue にする。
- **直そうとしている現象を、直す前に再現する。** 再現していないものは、直ったことも確認できない。実データで条件が揃わないなら条件を作る。書かれた再現条件は1つで止めず全部通し、直した後も同じ条件を全部通す。原因で束ねて直したときは、束ねた元の1件ずつに戻って確かめる。
- **証跡の無い主張はしない。** 読んで通ると判断したもの、前回通ったから今回も通ると考えたものは未確認で、「確認した」と書かない。結果は出力と画面から引く。測れなかったものは「未実施」と書き、空欄にも「問題なし」にもしない。
