# 検査を足すときのルール

- **検査を書く前に、その規約を破れる経路を実装から数える。** 設定・別の綴り・逆向きの走査で片側だけ塞ぐと、残した側が抜け道になる。
- **足した検査は、破る例が落ちることと通す例が通ることの両方をテストで固定する。** どちらかを欠くと、何にも当たっていない検査か、正当な入力を落とす検査が入る。
- **規約が成り立つ経路を実装と設定から数え、全部を同じ判定で見る。** 数え落とすと片側だけを塞いだ検査になり、経路ごとに判定を分けると通る入力が変わる。
- **走査や読み取りの失敗も、素の例外ではなく理由の1行にして落とす。** スタックトレースは、どの入力がなぜ駄目かを次の人に伝えない。
