# 検査を足すときのルール

- **検査を書く前に、その規約が成り立つ経路を実装と設定と依存の型定義から数え、全部を同じ判定で見る。** 設定・別の綴り・逆向きの走査・依存が持つ別名や別のノード型を数え落とすと片側だけを塞いだ検査になり、経路ごとに判定を分けると残した側が抜け道になる。
- **足した検査は、破る例が落ちることと通す例が通ることの両方をテストで固定する。** どちらかを欠くと、何にも当たっていない検査か、正当な入力を落とす検査が入る。
- **検査が落ちるときは、どの入力でも理由の1行を出す。** 読み取りに失敗する入力を素の例外のまま通すと、同じ入力で報告の形が検査ごとに変わる。
