# 検査を足すときのルール

- **検査を書く前に、その規約が成り立つ経路を実装と設定から数え、全部を同じ判定で見る。** 設定・別の綴り・逆向きの走査を数え落とすと片側だけを塞いだ検査になり、経路ごとに判定を分けると残した側が抜け道になる。
- **足した検査は、破る例が落ちることと通す例が通ることの両方をテストで固定する。** どちらかを欠くと、何にも当たっていない検査か、正当な入力を落とす検査が入る。
- **判定を広げたら、広げた先で当たる対象でない綴りを数える。** 語の列やノードの辿り方を緩めた分だけ、比較・添字・初期値の違うプロパティのような規約と関係ない綴りに当たり、逃げ道の無い経路で正当な入力を落とす。
- **別のファイルが持つ綴りの一覧は、読み取りや正規表現で拾わず `import` して引く。** 走査は改名・引用符・コメントで静かに取りこぼし、何にも当たらない検査が緑のまま残る。
- **フックは判定できない入力を黙って通す。** 読み取りや解析に失敗した回にツール呼び出しを止めると、フック自身の不具合でセッションが進まなくなる。
