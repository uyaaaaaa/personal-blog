# ドキュメントのルール

**原則としてドキュメントは書かない。実装が正で、実装を読めば分かることは書かない。**

文書は実装と一緒には更新されず必ず乖離し、乖離した文書は無いより有害。実装・lint・Git 履歴・issue が持てるものは、そちらに持たせる。

## 書かないもの

実装の写し（値、構造、props、ディレクトリツリー）、コンポーネントや関数に閉じた設計、機械が落とすもの、機械が守っている旨の説明（→ [ADR 11](../../docs/adr/11-no-enforcement-inventory.md)）、すぐ直せる小さな変更、既知の課題や TODO の一覧、最終更新の日付。

## 書くもの

| 何を | どこに |
| :--- | :--- |
| 下の基準を満たす判断 | `docs/adr/NN-<英語スラッグ>.md` に1判断1ファイル。索引は `docs/DECISIONS.md` |
| デザインの大方針とガードレール | `docs/DESIGN_GUIDELINE.md` |
| 構造・依存方向・検査の置き場 | `docs/ARCHITECTURE.md` |
| favicon / OGP の仕様と生成手順 | `docs/ICON_GUIDELINE.md` |

方針が変わったら、同じ変更で該当箇所を直すか消す。理由が失効した項目は消す。

## ADR の基準

次の**両方**を満たすときだけ書く。迷ったら書かない側に倒す。

1. **思想が反映される。** アーキテクチャ設計・規約、テスト設計、デザインの大方針のどれかに当たる
2. **簡単には変えられない。** 覆すと複数ファイル・公開 URL・ビルド設定・テストの走らせ方が変わる。または一度出すと戻せない

既存の方針を覆したときは必ず書く。書き方は既存の ADR に揃える（判断を言い切る見出し1行と、検討した案 / 対価 / 戻す条件の3つ）。番号は連番で、消したら詰め直し、索引の行も同じ変更で直す。
