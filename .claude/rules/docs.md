# ドキュメントのルール

**実装が正**で、ドキュメントは実装に追従させる。

- **UI を変えたら `docs/spec/` の該当ファイルを同じ変更で直す。** どのファイルかは [docs/spec/README.md](../../docs/spec/README.md) の表で引く。トークン・レイアウト原則・UX要件に触れる変更は `docs/DESIGN_GUIDELINE.md` も直す。
- **実装から読み取れない理由は、コードコメントではなく spec に書く。** 「一見不要な指定が必要な理由」「試して戻した案」「外部（ブラウザ・ライブラリ・Cloudflare）の都合」が対象。
- **判断の記録も spec と DESIGN_GUIDELINE に書く。** ADR のディレクトリは持たない。
- **構造（ディレクトリ、依存方向、lint の範囲）を変えたら `docs/ARCHITECTURE.md` を直す。** そこは「これから寄せる先」ではなく現状の説明。
- **「最終更新」のような日付を書かない。** Git が持っている。
- 記事（`content/article/`）を書く・直すときは `article` スキルに従う。
