# ドキュメントのルール

## 書かないもの

実装の写し（値、構造、props、ディレクトリツリー）、コンポーネントや関数に閉じた設計、機械が落とすもの、機械が守っている旨の説明、すぐ直せる小さな変更、既知の課題や TODO の一覧、最終更新の日付。

## 書くもの

| 何を | どこに |
| :--- | :--- |
| 下の基準を満たす判断 | `docs/adr/` に1判断1ファイル |
| デザインの大方針とガードレール | `docs/DESIGN_GUIDELINE.md` |
| 構造・依存方向・検査の置き場 | `docs/ARCHITECTURE.md` |
| favicon / OGP の仕様と生成手順 | `docs/ICON_GUIDELINE.md` |

理由が失効した項目は消す。

## ADR の基準

**覆すと公開 URL かディレクトリ全体が動く判断だけを書く。** 迷ったら書かない側に倒す。依存方向や取得の置き場のように1行で言える線は、規約（`.claude/rules/`）か lint に置く。

**運用の設計は書かない。** 整形・検査をどのツールに置くか・テストの置き場と走らせ方・デザインの大方針は、置き場が別にある（上の表）。1つのファイルの中で閉じる規約も書かない。

見出しは判断を言い切る1行にする。
