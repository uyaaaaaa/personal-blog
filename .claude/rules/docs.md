# ドキュメントのルール

## 書かないもの

実装の写し（値、構造、props、ディレクトリツリー）、コンポーネントや関数に閉じた設計、機械が落とすもの、機械が守っている旨の説明、すぐ直せる小さな変更、既知の課題や TODO の一覧、最終更新の日付。

## 書くもの

| 何を | どこに |
| :--- | :--- |
| 下の基準を満たす判断 | `docs/adr/` に1判断1ファイル |
| デザインの大方針とガードレール | `docs/DESIGN_GUIDELINE.md` |
| 構造・依存方向・検査の置き場 | `docs/ARCHITECTURE.md` |
| favicon / OGP の仕様と生成手順 | `docs/ICON_GUIDELINE.md` |

理由が失効した項目は消す。

## ADR の基準

次の**両方**を満たすときだけ書く。迷ったら書かない側に倒す。

1. **ディレクトリ構造か依存関係に影響する。** ファイルの置き場、層の間の依存方向、公開 URL の形のどれかが変わる
2. **簡単には変えられない。** 覆すと複数ファイルの置き場か import の向きが動く。または一度出すと戻せない

**運用の設計は書かない。** 整形・検査をどのツールに置くか・テストの走らせ方・デザインの大方針は、置き場が別にある（上の表）。1つのファイルの中で閉じる規約も書かない。

見出しは判断を言い切る1行にする。

## エージェントに渡す散文

**1行ずつ「消すと Claude が間違えるか」を問う。** 間違えないなら書かない。

置き場は、効かせたい範囲に足りる一番下の層を選ぶ。

| 種類 | 読まれるタイミング | 置いてよいもの |
| :--- | :--- | :--- |
| `CLAUDE.md`、`paths` の無い rule、`paths: "**"` の rule、全 skill と agent の description | 毎セッション | 毎回効く事実だけ。落とすと同じ間違いを繰り返すもの |
| `paths` 付きの rule | 該当ファイルを開いたとき | そのファイル種別に閉じた判断 |
| コード内のコメント | 該当ファイルを開いたとき | 判定は `.claude/rules/comment.md` が持つ。ここでは基準を書き直さない |
| skill の本体 | 依頼が該当したとき | 手順。フェーズごとに参照する文書はさらに別ファイルに分ける |
| agent の本体 | 投げられたとき | 投げた先で完結する手順。判断はメインに残す |
| `docs/` と ADR | 参照されたとき | 上の「書くもの」と「ADR の基準」 |
