# ドキュメントのルール

**実装が正**で、ドキュメントは実装に追従させる。実装を読めば分かること（値・構造・props）を写した文書は持たない。

- **実装から読み取れない理由は、コードコメントではなく判断の記録に書く。** 「一見不要な指定が必要な理由」「試して戻した案」「外部（ブラウザ・ライブラリ・Cloudflare）の都合」が対象。置き場は下の表で決める。
- **理由が無くなったら項目を消す。** 実装を変えて判断が変わったときは、該当項目を同じ変更で直すか消す。
- **トークン・レイアウト原則・UX要件に触れる変更は `docs/DESIGN_GUIDELINE.md` も直す。** 解消した課題は既知の課題から消す。
- **構造（ディレクトリ、依存方向、lint の範囲）を変えたら `docs/ARCHITECTURE.md` を直す。** そこは「これから寄せる先」ではなく現状の説明。
- **「最終更新」のような日付を書かない。** Git が持っている。
- 記事（`content/article/`）を書く・直すときは `article` スキルに従う。

## 判断の記録の書き方

`docs/DECISIONS.md` は索引で、中身は `docs/adr/` と `docs/decisions/` にある。項目を足したら索引の行も同じ変更で足す。

- 1項目は「**判断**」＋「理由」。理由が無い項目は書かない（理由が失効したら項目ごと消せるように）。
- 見出しはコンポーネント名やファイル名で引けるようにする。

判断には2種類あり、置き場を分ける。迷ったら「別の案でも動いたか」で決め、動いたなら前者。

| | 構造に関わる判断 | 実装上の制約 |
| :--- | :--- | :--- |
| 何か | **動く選択肢が2つ以上あった**うえで選んだもの | ブラウザ・ライブラリ・Cloudflare の都合で**そうするしかない**もの |
| 影響 | 複数ファイル、URL、ビルド設定、方針に及ぶ | 1つのコンポーネントや行に閉じる |
| 覆すとき | 覆す条件が言える。覆すと設計や URL が変わる | 制約が消えたら行を消すだけ |
| 書くこと | 判断・検討した案・対価・戻す条件 | 判断・理由 |
| 置き場 | `docs/adr/NN-<英語スラッグ>.md` に1判断1ファイル | `docs/decisions/<画面・機能>.md` の該当節 |

前者は ADR なので、「検討した案 / 対価 / 戻す条件」の3つを必ず持つ。番号は連番で、消した番号は再利用しない。
検討した案が2つ以上あるときは、1つの段落に `(1)(2)(3)` と詰めず、**案ごとに1行の入れ子の箇条書き**にする。行頭は案の名前を太字にし、採用した案には `（採用）` を付ける。対価が3つ以上に分かれるときも同じにする。

```md
- **検討した案**
  - **クエリ（`?page=2`）**: 静的生成では2ページ目以降が生成されない。
  - **パス（`/article/page/2`、採用）**: `crawlLinks` がページャを辿って全ページを生成する。
- **対価**: …
- **戻す条件**: …
```

後者を ADR にはしない。選択肢が無いものに「検討した案」は書けず、空欄のテンプレートが増えるだけ。
