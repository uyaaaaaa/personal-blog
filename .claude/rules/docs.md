# ドキュメントのルール

**実装が正**で、ドキュメントは実装に追従させる。コンポーネントの値・構造・props を写した文書は持たない。

- **実装から読み取れない理由は、コードコメントではなく `docs/DECISIONS.md` に書く。** 「一見不要な指定が必要な理由」「試して戻した案」「外部（ブラウザ・ライブラリ・Cloudflare）の都合」が対象。該当する画面・機能の節に、太字の判断＋理由の1項目として足す。
- **理由が無くなったら項目を消す。** 実装を変えて判断が変わったときは、DECISIONS.md の該当項目を同じ変更で直すか消す。
- **トークン・レイアウト原則・UX要件に触れる変更は `docs/DESIGN_GUIDELINE.md` も直す。** 既知の課題を解消したら 6 の行を消す。
- **構造（ディレクトリ、依存方向、lint の範囲）を変えたら `docs/ARCHITECTURE.md` を直す。** そこは「これから寄せる先」ではなく現状の説明。
- **ADR のディレクトリは持たない。** 判断の記録は DECISIONS.md と DESIGN_GUIDELINE に書く。
- **「最終更新」のような日付を書かない。** Git が持っている。
- 記事（`content/article/`）を書く・直すときは `article` スキルに従う。
