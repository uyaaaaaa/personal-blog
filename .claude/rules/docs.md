# ドキュメントのルール

**原則としてドキュメントは書かない。実装が正で、実装を読めば分かることは書かない。**

文書は実装と一緒には更新されず必ず乖離し、乖離した文書は無いより有害。実装・lint・Git 履歴・issue が持てるものは、そちらに持たせる。

## 書かないもの

実装の写し（値、構造、props、ディレクトリツリー）、コンポーネントや関数に閉じた設計、機械が落とすもの、機械が守っている旨の説明、すぐ直せる小さな変更、既知の課題や TODO の一覧、最終更新の日付。

## 書くもの

| 何を | どこに |
| :--- | :--- |
| 下の基準を満たす判断 | `docs/adr/NN-<英語スラッグ>.md` に1判断1ファイル。索引は `docs/DECISIONS.md` |
| デザインの大方針とガードレール | `docs/DESIGN_GUIDELINE.md` |
| 構造・依存方向・検査の置き場 | `docs/ARCHITECTURE.md` |
| favicon / OGP の仕様と生成手順 | `docs/ICON_GUIDELINE.md` |

方針が変わったら、同じ変更で該当箇所を直すか消す。理由が失効した項目は消す。

## ADR の基準

次の**両方**を満たすときだけ書く。迷ったら書かない側に倒す。

1. **ディレクトリ構造か依存関係に影響する。** ファイルの置き場、層の間の依存方向、公開 URL の形のどれかが変わる
2. **簡単には変えられない。** 覆すと複数ファイルの置き場か import の向きが動く。または一度出すと戻せない

**運用の設計は書かない。** 整形・検査をどのツールに置くか・テストの走らせ方・デザインの大方針は、置き場が別にある（上の表）。1つのファイルの中で閉じる規約も書かない。

この基準に当たる方針を覆したときは必ず書く。見出しは判断を言い切る1行にする。
