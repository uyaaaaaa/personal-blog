# 置き場とデータの流れ

- **composable にするのは「reactive / lifecycle を使う」かつ「2箇所以上で使う」ロジックだけ。** 純粋関数は `app/utils/` へ、1箇所でしか使わないものはそのコンポーネントの中に置く。抽出は2回目の使用時に行い、**テストを2回目の使用とみなす**。
- **モジュールスコープに可変値を置くのは、SSR でリクエスト間に共有されても壊れない値に限る。**
- **route に依存する取得を呼ぶのは、そのルートを所有する `pages/` だけ。** route の値で結果が変わらない取得は、それを出すコンポーネントが自分で呼ぶ。
- **リロード・共有・戻るで保持されるべき状態は URL に持たせ、URL から導く。** 別の state に複製しない。URL が表現できない値（範囲外のページ番号、存在しないカテゴリ）は 404 にする。
- **同じ値の正本を2箇所に作らない。** スキーマと表示名のように分けざるを得ないときは、同じ変更で両方を直す。
- **`useScrollFrame` に渡す読み取りは、他の読み取りの書き込み結果に依存できない。**
- **表示の出し分けは CSS が行い、JS は購読を止めるだけにする。** `v-if` で消さない。
- **ビルド時刻が焼き付く値はクライアントで計算する。**
- **出し分け・分岐・ルーティングを触ったら、テストと build の成否で止めず `dist/` の生成された HTML まで見る。**
- **`components/ui/` に置くのは題材を知らない部品だけ。** 記事・サイト構造・Markdown 記法・エラー状態のどれかを知っているものは、それを知る領域に置く。`ui/` へ出すときは、題材を知っている部分を props に追い出してから出す（→ [ADR 07](../../docs/adr/07-ui-knows-no-domain.md)）。
- **`pages/` 配下でルートにしないファイルは、`-` 始まりの名前にする。**
- **複数のルートファイルに跨る一覧は、本体を1つの実体に出す。**
