# 置き場とデータの流れ

- **composable にするのは「reactive / lifecycle を使う」かつ「2箇所以上で使う」ロジックだけ。** 純粋関数は `app/utils/` へ、1箇所でしか使わないものはそのコンポーネントの中に置く。抽出は2回目の使用時に行い、**テストを2回目の使用とみなす**。
- **モジュールスコープに可変値を置くのは、SSR でリクエスト間に共有されても壊れない値に限る。**
- **route に依存する取得を呼ぶのは、そのルートを所有する `pages/` だけ。** route の値で結果が変わらない取得は、それを出すコンポーネントが自分で呼ぶ（理由は [ADR 05](../../docs/adr/05-fetch-follows-route-dependency.md)）。カード・棚・目次のような、置かれる場所で中身が変わる部品は props で受け取る。
- **リロード・共有・戻るで保持されるべき状態は URL に持たせ、URL から導く。** 別の state に複製しない。URL が表現できない値（範囲外のページ番号、存在しないカテゴリ）は 404 にする。
- **同じ値の正本を2箇所に作らない。** スキーマと表示名のように分けざるを得ないときは、同じ変更で両方を直す。
- **スクロール・リサイズの読み取りは1フレームに集約される。** 読み取りは他の読み取りの書き込み結果に依存できない。
- **表示の出し分けは CSS が行い、JS は購読を止めるだけにする。** `v-if` で消すと SSR が出す HTML が変わる。
- **ビルド時刻が焼き付く値はクライアントで計算する。** 静的生成なので、ビルド時に決めた値はページの寿命の間そのまま出る。
- **`components/ui/` に置くのは題材を知らない部品だけ。** 記事・サイト構造・Markdown 記法・エラー状態のどれかを知っているものは、それを知る領域に置く。領域をまたいで使いたくなったら、題材を知っている部分を props に追い出してから `ui/` へ出す（理由は [ADR 07](../../docs/adr/07-ui-knows-no-domain.md)）。
- **1コンポーネント1ファイル。** ページ番号の分だけルートファイルが増える一覧（[ADR 01](../../docs/adr/01-page-number-in-path.md)）は、本体を `pages/` 配下に `-` 始まりのファイル名（Nuxt のスキャン除外規則）で置き、ルートファイルはそれを import して描画する。
