# 置き場とデータの流れ

- **composable にするのは「reactive / lifecycle を使う」かつ「2箇所以上で使う」ロジックだけ。** 純粋関数は `app/utils/` へ、1箇所でしか使わないものはそのコンポーネントの中に置く。抽出は2回目の使用時に行い、**テストを2回目の使用とみなす**（理由は [ADR 08](../../docs/adr/08-test-as-second-use.md)）。
- **composable は state と関数だけを返し、DOM を作らない。** モジュールスコープに可変値を置くのは、SSR でリクエスト間に共有されても壊れない値に限る。
- **route に依存する取得を呼ぶのは、そのルートを所有する `pages/` だけ。** route の値で結果が変わらない取得は、それを出すコンポーネントが自分で呼ぶ（理由は [ADR 13](../../docs/adr/13-fetch-follows-route-dependency.md)）。カード・棚・目次のような、置かれる場所で中身が変わる部品は props で受け取る。
- **記事のクエリには、公開制御と、必要なフィールドだけの絞り込みを必ず付ける。**
- **リロード・共有・戻るで保持されるべき状態は URL に持たせ、URL から導く。** 別の state に複製しない。URL が表現できない値（範囲外のページ番号、存在しないカテゴリ）は 404 にする。
- **同じ値の正本を2箇所に作らない。** スキーマと表示名のように分けざるを得ないときは、同じ変更で両方を直す。
- **スクロール・リサイズの読み取りは1フレームに集約される。** 読み取りは他の読み取りの書き込み結果に依存できない。
- **表示の出し分けは CSS が行い、JS は購読を止めるだけにする。** `v-if` で消すと SSR が出す HTML が変わる。
- **ビルド時刻が焼き付く値はクライアントで計算する。** 静的生成なので、ビルド時に決めた値はページの寿命の間そのまま出る。
- **`components/` の領域をまたぐ依存は、`article/` が `common/` を使う1本だけにする。** `layout/` は他の領域を使わない。
- **1コンポーネント1ファイル。** ルートファイルは実体コンポーネントを描画するだけにし、ロジックを持たせない。ページ番号の分だけルートファイルが増える一覧（[ADR 01](../../docs/adr/01-page-number-in-path.md)）は、本体を `pages/` 配下に `-` 始まりのファイル名（Nuxt のスキャン除外規則）で置き、ルートファイルはそれを import して描画する。
- **テストは実装の隣に `*.test.ts` で置く。** `app/pages/` には置かない（ルートファイルはロジックを持たない）。理由は [ADR 06](../../docs/adr/06-tests-next-to-source.md)。
