# 置き場とデータの流れ

- **composable にするのは「reactive / lifecycle を使う」かつ「2箇所以上で使う」ロジックだけ。** 純粋関数は `app/utils/` へ、1箇所でしか使わないものはそのコンポーネントの中に置く。抽出は2回目の使用時に行う。
- **composable は state と関数だけを返し、DOM を作らない。** モジュールスコープに可変値を置くのは、SSR でリクエスト間に共有されても壊れない値に限る。
- **データ取得を呼ぶのは、そのルートを所有する層だけ。** カード・棚・目次のような部品は props で受け取る。
- **記事のクエリには、公開制御と、必要なフィールドだけの絞り込みを必ず付ける。**
- **リロード・共有・戻るで保持されるべき状態は URL に持たせ、URL から導く。** 別の state に複製しない。URL が表現できない値（範囲外のページ番号、存在しないカテゴリ）は 404 にする。
- **同じ値の正本を2箇所に作らない。** スキーマと表示名のように分けざるを得ないときは、同じ変更で両方を直す。
- **スクロール・リサイズの購読はアプリ全体で1本にまとめる。** 個別に `addEventListener` しない。1フレームに集約するので、読み取りは他の読み取りの書き込み結果に依存できない。
- **表示の出し分けは CSS が行い、JS は購読を止めるだけにする。** `v-if` で消すと SSR が出す HTML が変わる。
- **1コンポーネント1ファイル。** ルートファイルは実体コンポーネントを描画するだけにし、ロジックを持たせない。
