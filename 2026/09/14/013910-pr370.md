# PR #370 で受けた指摘

## must: ビルド時の hook が dev でも発火して未処理の rejection になる

`compiled` は dev の rollup watcher から await されずに呼ばれる。生成物を前提にした処理を
そこに置くと、起動と再ビルドのたびに unhandledRejection が出る。
直し方: `nitro.options.dev` なら何もせず返す。

- 経路を数えるとき、同じ hook が dev から発火する道を見落としていた

## must: ファイル名からパスを組み直すと collection の綴りと割れる

collection のパスは `slugify(refineUrlPart(stem))` が決める。ファイル名をそのまま使うと
大文字や記号を含む名前で食い違い、出ていないパスとしてビルドが落ちる。
直し方: 導出を揃えるのではなく持たない。組み上がった collection の DB から `path` を読む。

- 正本のある値を、手元で組み直せる形に見えたからといって組み直していた

## suggestion: コメントに書いた理由が、実際の理由と違う

「自動収集はプリレンダより先に走る」と書いたが、実際は同じ `compiled` の中で
プリレンダの後に走っている。外す理由は、畳まずに上限超過分を黙って切ること。

- 外部の挙動をコメントに書くとき、書いた理由を実装で裏取りしていなかった
