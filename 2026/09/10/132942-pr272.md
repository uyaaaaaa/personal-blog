# PR #272 で受けた指摘

## must: テーマのクラスの片側しか見ていない

`.dark` だけを検査の対象にし、`.light` を落とさなかった。`colorMode` の `classSuffix` が空なのでライトも html のクラスで表れる。
直し方: セレクタの判定を `.dark` と `.light` の両方にした。

規約を機械に移すとき、その規約が成り立つ経路を実装（設定を含む）から数え、片側だけ塞いだ検査を出さない。

## suggestion: 綴りの末尾だけで色のクラスを判定した

`dark:` の後ろの末尾がトークン名なら落としたため、`dark:box-border` `dark:align-sub` のような色を取らないクラスまで落ちた。
検査のメッセージが「通す」と書いた DOM の出し分けを、検査自身が落としていた。
直し方: 色を取る接頭辞（`text-` `bg-` `border-` 等）から見る形に絞り、通す例をテストで固定した。

落とす例だけをテストし、通す例を固定していなかった。

## imo: 同じ規約の経路ごとに判定が違った

クラスの綴りは template の属性しか読まず、`@apply dark:text-main` は postcss 側にもクラス側にも当たらなかった。
直し方: 判定の正規表現を検査の側に置き、template と `@apply` で同じものを使うようにした。

同じ規約を複数の経路で見るときは、文面ではなく判定そのものを共有する。
