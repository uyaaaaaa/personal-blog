# PR #525 で受けた指摘

## 集約で外した try が、読み取り以外の失敗まで拾っていた（must 2）

読み取りを1本に集約したとき、元の try/catch が拾っていた範囲を数え落とした。設定の辿る先が欠けた回（`hooks` の各段が null）と、読めたが形の違う入力（`package.json` に `scripts.lint` が無い）が、素の TypeError で落ちた。

直し方: 辿る各段を省略可能な参照にし、入口が無い入力は理由の1行で落とす。欠け方をテストで固定した。

観点: **読み取りを集約するときは、元の try が拾っていた失敗を数え直す。** 読み取りの失敗だけを移すと、同じ catch が拾っていた形の失敗が素の例外に戻る。

## 残した catch の見出しが、届く失敗と合わなくなった（suggestion 3）

読み取りがその場で落ちるようになったので、`記事を読み取れない` `タグを読み取れない` `読めない` の3つには解析の失敗しか届かなくなった。文言を解析の失敗と分かる形に直した。

観点: **失敗の出口を移したら、残った出口の文言が指すものを見直す。**

## 経路を数え落とした lint（suggestion 2）

`JSON.parse` を受け手（`callee.object.name`）で見ていたので、`globalThis.JSON.parse` と束縛（`const parse = JSON.parse` / `const { parse } = JSON`）が抜けた。呼ぶ手前の綴り（MemberExpression）で見る形に直した。selector を足したのに破る例をテストに書かなかったものもあった（`require` / `createRequire`）。

観点: **足した selector は1本ずつ破る例を書く。** 数だけ足しても、当たっていない本が混ざる。

## 根の導出が2箇所に増えた（suggestion 1）

呼び出し側と `articleFiles` が同じ引数で別々に根を解決していた。読む口ごと返す形にして1箇所に戻した。

観点: **集約先を作ったら、通る側が同じ導出を持たない。**
