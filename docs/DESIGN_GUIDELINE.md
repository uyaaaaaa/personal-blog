# Design Guideline

当ブログのデザインの**大方針とガードレール**を定めるドキュメントです。
コンセプト、デザイントークンの原則、レイアウトの原則、UX 要件といった「サイト全体に横断的に効くルール」だけを扱います。

**実装が正**です。個々のコンポーネントの値や構造、画面ごとの制約は書きません。
方針を覆したときは、同じ変更でこの文書を直し、必要なら [判断の記録](./DECISIONS.md) に ADR を足します。
アイコン・favicon の仕様は [ICON_GUIDELINE.md](./ICON_GUIDELINE.md) にあります。

- 対象: Nuxt 4 / Nuxt Content 3 / Tailwind CSS 3 (+ @tailwindcss/typography)

---

## 1. デザインコンセプト

| 項目 | 詳細 |
| :--- | :--- |
| **コアコンセプト** | **「Functional Minimalism for Experts」**<br>無駄な装飾を徹底的に排除し、コードと情報の高速な認知に特化した機能美を追求する。 |
| **ムード** | 洗練、プロフェッショナル、クリーン、高速。 |
| **表現方法** | 白ベースのフラットデザイン。1pxのボーダーと余白でセクションを区切り、色彩はアクセント1色に限定する。 |

### 設計原則

新しい要素をデザインする際は、以下の原則に従います。

1. **色ではなくボーダーと余白で区切る。** 面を塗って区切らない。常時影のついた要素は作らない。影は重なりを示すためだけに使う（ホバー、sticky 到達、本文の上に重なる一時的な面）。例外は Callout の背景と `diff` コードブロックの行背景だけ。
2. **アクセントカラーは1色のみ。** 意味のある箇所（リンク、アクティブ状態、ホバー）にのみ使い、装飾には使わない。
3. **画像よりテキスト。** サムネイル画像に依存せず、絵文字とテキスト情報で記事を識別させる。
4. **Webフォントを読み込まない。** 表示速度を優先し、OSネイティブフォントで完結させる。
5. **技術的な情報には等幅フォントを使う。** 日付、タグ、ロゴ、セクション見出しなど。

## 2. デザイントークン

### A. 単一情報源

色・フォント・サイズの値は **`theme/tokens.ts` の1箇所だけ**に定義します。`tailwind.config.ts` がこれを読み、CSS 変数と Tailwind theme を生成します。

- **色・フォントを追加・変更するときは `theme/tokens.ts` だけを編集する。** コンポーネントにはトークン由来のクラスか CSS 変数で書き、直値を書かない。
- **ダークテーマはトークンの再定義で成立させる。** `.dark` 配下で CSS 変数を再定義するだけで全体が切り替わる。`dark:` で色を分岐しない。
- **サイズは Tailwind のスケールか `sizes` の名前で書く。** スケールに無い値は `sizes` に名前を足してから使う。角括弧を含む任意値（`w-[264px]`）は書かない（→ [ADR 09](./adr/09-size-tokens-and-no-arbitrary-values.md)）。

パレットの外側で、直値を書いてよいもの。

| 例外 | 理由 |
| :--- | :--- |
| 白・黒とその透過 | テーマによらず同じでよい（スクリムなど） |
| ロゴマークの SVG | 固定色の意匠として確定済み。仕様は [ICON_GUIDELINE.md](./ICON_GUIDELINE.md)。アクセント色を含むため、パレットを変えたらこちらも直す |
| コードブロックの構文色 | Shiki のテーマ（`github-light` / `github-dark`）由来。上書きすると構文色の情報源が2つに割れる |
| 記事本文（prose）の色 | `@tailwindcss/typography` の `prose-slate` / `dark:prose-invert` 由来 |
| Callout の配色 | Obsidian デフォルトテーマの色相をベースにした独自パレット。両テーマでタイトル文字のコントラスト比 4.5:1 以上を保つ |

### B. 配色

- **色を持つのは `accent` だけ。** リンク、タグ枠、ホバー、アクティブな目次項目、ロゴのスラッシュ。それ以外は無彩色で組む。
- **コントラスト比は 4.5:1 以上を保つ。** アクセント色で塗った面の上の文字も含む。
- **`diff` の追加行・削除行は行全体の背景を塗る。** 設計原則 1 に対する意図的な例外。差分は「どの行が変わったか」を面で追う情報と位置づける。行の中で変化した語はさらに濃い背景で示し、行頭の `+` / `-` と語の文字色は本文色にする（テーマの赤・緑では濃い背景の上でコントラストが足りない）。

### C. タイポグラフィ

- **OSネイティブフォントを優先し、Webフォントは読み込まない。** 表示速度を最優先するため。
- **`font-mono` はコード以外にも当てる。** 技術的な記号性を出す目的で、ロゴ、日付、タグ名、セクション見出し、ラベル、エラーコードが対象。
- **行間は `body` で一括して決める。**

### D. モーション

- **トランジションは `200ms`（色・影）/ `300ms`（変形・開閉）/ `500ms`（画像ズーム）の3段階から選ぶ。**
- **`prefers-reduced-motion` は参照しない。** OS の「視差効果を減らす」設定に関わらず常に同じように動く。`@media` も `matchMedia` も置かない（→ [ADR 02](./adr/02-no-prefers-reduced-motion.md)）。
- **`html` に `scroll-behavior: smooth` は置かない。** ページ遷移とブラウザバックの位置復元までアニメーションしてしまう。ページ内ジャンプは JS 側で `behavior: 'smooth'` を指定する。

### E. ブレークポイント

**`md`（768px）と `lg`（1024px）の2つだけ。** 表示・非表示の切り替えは Tailwind の `md:` / `lg:` に統一し、scoped CSS に独自の境界値を書きません。Tailwind 側と 1px ずれて表示が破綻するためです。

`md` で記事グリッドが 2 カラムに、`lg` で 3 カラムと記事詳細の 2 カラム（サイドバー表示）になります。

## 3. レイアウトの原則

### A. 全ページ共通

sticky なヘッダー、`.container` で幅を絞った `main`、フッターを縦に積み、コンテンツが短くてもフッターを最下部に置きます。ヘッダーは半透明 + `backdrop-filter` で、スクロール時に背後のコンテンツを透かします。

**ページヘッダーの共通形式**: `h1` + 説明文（サブテキスト色）+ 下端に 1px ボーダー。

### B. 記事一覧

TOP 以外の一覧（全記事、タグ、カテゴリ）は同じグリッドを使います。

- SP は 1 カラム、`md` で 2、`lg` で 3。
- 並び順は `date` の降順。表示対象は `published: true` の記事のみ。
- 一定件数で区切ってページャを置き、ページ番号はパスで持つ（→ [ADR 01](./adr/01-page-number-in-path.md)）。範囲外のページ番号は 404。
- 一覧ページの下端には戻り導線を置く。

### C. TOP

TOP は Hero（最新1件）とカテゴリごとの棚を縦に積みます。

- **棚は「見せ場」であり、カテゴリの索引ではない。** 索引はヘッダーの `Explore` が持つ。全カテゴリの一覧ページは持たない。
- Hero に出した記事は棚から除外する。同じカードを1画面に2回出さない。
- Hero にはカテゴリのチップを出す。TOP だけを見た読者にもカテゴリという軸の存在が見えるようにする。

### D. 記事詳細

- `lg` 以上はメインカラムと右サイドバー（目次）の 2 カラム。サイドバーは sticky で追従する。
- SP は 1 カラムになり、目次は記事タイトル直下の sticky バーに切り替わる。

## 4. 記事本文（Markdown）の方針

- **タイポグラフィのベースに任せる。** 見出し・引用・リストなどは `prose` の体裁を活かし、必要な差分だけを整える。
- **記法は Obsidian 互換を優先する。** 執筆環境（Obsidian）でそのまま書ける記法を採用する（Callout など）。
- **コードの可読性を最優先する。** ハイライトは Shiki のデュアルテーマでサイトのテーマに追従させ、背景とボーダーでコード領域を明示する。
- **コードにはファイル名を添えられるようにする。** ラベルはコードブロックの上部に出し、面は塗らず 1px ボーダーで区切る（設計原則 1）。
- **差分は行で見せ、変化した語を濃く示す。** 2-B のとおり。

## 5. 機能性とUX要件

サイト全体で満たす要件です。

| 項目 | 要件 |
| :--- | :--- |
| **パフォーマンス** | 表示速度を最優先する。Webフォントを読み込まない |
| **静的生成** | Cloudflare Pages 向けにプリレンダリングし、プリレンダ済みのパスは Worker を通さない。存在しないパスは静的な `404.html` が 404 で返す |
| **公開制御** | `published: true` の記事のみを全ページで取得する |
| **旧URL互換** | `/blog/**` `/book/**` は `/article/**` へ301リダイレクトする |
| **タグ** | 全タグの一覧ページと、タグによる絞り込みを提供する。タグは URL のセグメントになるため、スラッグは一意でなければならない |
| **カテゴリ** | サイト設計として固定する値。`content.config.ts` の `z.enum` を正とし、値をそのまま URL セグメントに使う |
| **ページネーション** | 記事一覧を一定件数で区切り、ページ番号はパスで持つ（→ [ADR 01](./adr/01-page-number-in-path.md)） |
| **スクロール追従** | 見出し位置に応じて目次のアクティブ項目をハイライトする |
| **スムーズスクロール** | 見出し・目次のクリックでスムーズに移動し、URLハッシュを更新する。着地位置は CSS（`scroll-margin-top`）で一元管理し、JS でオフセットを足さない |
| **先頭に戻る** | 記事詳細の SP 幅でのみ、読み進めたら右下にボタンを浮かべる |
| **脚注** | 本文の参照と記事末尾の脚注を相互にジャンプできる。固定ヘッダーやモバイル目次バーに潜り込ませない |
| **UI文言** | ナビゲーション、ボタン、エラーなど UI 側の文言は**英語**を基本とする（記事本文は日本語） |
| **アイコン** | favicon / PWA / iOS 向けアイコンを一式提供する（→ [ICON_GUIDELINE.md](./ICON_GUIDELINE.md)） |
| **OGP** | SNS シェア用の OGP / Twitter Card メタタグを全ページに出力する。記事を表示できないページは `og:type` を `website` にする |
| **ローディング表示** | ルート遷移中は画面上端にアクセント色のバーを表示する。面を塗らずレイアウトも動かさない |
| **記事取得の状態分離** | 記事詳細では「取得失敗」と「記事なし」を区別して表示し、HTTP ステータスも実態に合わせる |
| **ダークモード** | Light / Dark / System を選べる。`System` は `prefers-color-scheme` に追従し、選択は永続化する。シンタックスハイライトと `theme-color` メタもテーマに追従する |

未実装の機能と修正待ちの不具合は [GitHub Issues](https://github.com/uyaaaaaa/personal-blog/issues) にあります。
