# Design Guideline

新しい要素を作るときに引く、デザインの判断基準です。**値・構造・機能の一覧は持ちません**（実装が正）。
原則を覆したときは同じ変更でここを直し、戻せない判断なら [ADR](./DECISIONS.md) を足します。アイコンの仕様は [ICON_GUIDELINE.md](./ICON_GUIDELINE.md) にあります。

---

## コンセプト

**Functional Minimalism for Experts.** 装飾を足さず、コードと情報を速く読ませることに全部寄せる。

迷ったら「読む速さが上がるか」で決める。上がらない変更は、綺麗になっても採らない。

---

## 原則

1. **区切りは線と余白で作る。** 面を塗って区切らない
2. **影は重なりを示すときだけ使う。** 常時影のついた要素を作らない
3. **色を持つのは `accent` の1色だけ。** 意味のある状態（リンク、アクティブ、ホバー）に使い、装飾には使わない
4. **画像よりテキスト。** サムネイルに依存せず、文字で記事を識別させる
5. **Web フォントを読み込まない。** 表示速度が先
6. **技術的な情報は等幅で書く。** 日付、タグ、ラベル、セクション見出し
7. **値は名前で書く。** 色もサイズも、トークンに名前があるものだけを使う（→ [ADR 09](./adr/09-size-tokens-and-no-arbitrary-values.md)）
8. **テーマの差はトークンの再定義だけで作る。** 色をテーマごとに分岐しない
9. **動きは短く、種類を増やさない。** 用途ごとに長さを1つ決める（→ [ADR 02](./adr/02-no-prefers-reduced-motion.md)）

---

## 守る線

変更のたびに目で確かめる。

- **コントラスト比 4.5:1 以上。** アクセント色で塗った面の上の文字も含む
- **ページ内ジャンプの着地位置は CSS で一元管理する。** JS でオフセットを足さない。`html` に `scroll-behavior: smooth` を置くと、ページ遷移とブラウザバックの位置復元までアニメーションする
- **`diff` は行の面で見せる。** 原則 1 に対する唯一の意図的な例外。差分は「どの行が変わったか」を面で追う情報と位置づける

---

## 破ってよいとき

**理由が外部にあるものだけ。** リポジトリを読んでも辿り着けない事情があるときに限り、原則 1 と 7 を破ってよい。

| 破ってよいもの | 外部の事情 |
| :--- | :--- |
| コードの構文色 | Shiki のテーマが持つ。上書きすると構文色の情報源が2つに割れる |
| 記事本文の体裁 | `@tailwindcss/typography` が持つ。差分だけを整える |
| Callout の配色 | Obsidian のテーマ由来。執筆環境でそのまま書けることを優先する |
| ロゴマーク | 意匠として確定済み（→ [ICON_GUIDELINE.md](./ICON_GUIDELINE.md)） |

---

## 画面の思想

実装を読んでも意図が分からないものだけ。

- **TOP の棚は見せ場であり、カテゴリの索引ではない。** 索引はヘッダーが持つ
- **同じカードを1画面に2回出さない**
- **記法は Obsidian 互換を優先する。** 執筆環境でそのまま書けることを、記法の綺麗さより優先する
- **UI の文言は英語。** 記事本文は日本語
