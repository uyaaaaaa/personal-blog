# 機械が集めたものは記事と別の URL 系統に出す

`/digest/<日付>/<slug>` に置き、`/article` の系統にも `category` の enum にも混ぜない。URL の形は収集物を置くキーの形そのものにする。

- **検討した案**
  - **記事の `category` を増やす**: `/category/*` が生え、トップに棚が増え、検索ダイアログとメガメニューが引く記事の dump にも載る。混ぜない先を数え上げて1つずつ出し分けで塞ぐことになり、数え落とした先から漏れる。
  - **頻度を URL に焼く（`/daily`）**: 動機は定期のスパンであって頻度ではない。日次を隔日に変えた日に、公開済みの URL が嘘になる。
  - **別の collection として `/digest` に出す（採用）**: 記事の一覧・タグ・カテゴリ・検索が引くのは記事の collection だけなので、混ざらないことが出し分けの条件ではなく collection の境界で決まる。
- **対価**: 公開制御が collection ごとに別になる。記事の下書きが本番に出るのを止める検査は記事の collection にだけ当たり、どの collection を引くか名指していないクエリは落とす側に残る。日付でネストする分、URL は記事より1段深くなる。
- **戻す条件**: 機械が集めたものを人が書いたものと同じ一覧に載せ、同じ検索で引けるようにすると決めたとき。公開済みの URL は戻せないので、`/digest` は残したまま転送する。
