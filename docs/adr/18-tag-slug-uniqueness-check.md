# タグのスラッグの一意性を lint で守る

記事のタグを全部集めてスラッグを突き合わせる検査を `npm run lint` に置き、スラッグが空になるタグと、既存のタグと同じスラッグになるタグを落とす。

- **検討した案**: (1) `content.config.ts` の zod でタグを制限する。実測では成立しない。`@nuxt/content` は schema をドキュメントの検証に使わず、`zodToJsonSchema` に渡して DB の列と型を作るためだけに使うため、`refine` も `regex` もビルドを落とさず、壊れたリンクがそのまま生成物に残る。(2) `content:file:afterParse` で throw する。content 側が例外を握りつぶして警告に変え、その記事がまるごと消えた状態で終了コード 0 になるため、元の不具合より悪い。(3) スラッグが空になったときだけ別の値にフォールバックする。空は消えるが、`Vue.js` と `vue js` のように英数字を含むタグ同士の衝突は残り、URL に非 ASCII か percent-encoding が出る。(4) スラッグにハッシュを足して単射にする。衝突は原理的に消えるが、公開済みの URL が全部変わる。(5) 検査を Vitest に置く。`npm test` の対象が「Nuxt を起こさない純粋関数」から「リポジトリの内容」へ広がる。(6) 検査を lint に置く（採用）。これは実装の振る舞いではなく入稿の規約で、`npm run lint` は既に Prettier・ESLint・dependency-cruiser という同じ役割の検査を集めている。URL は今の短い ASCII のまま変わらず、スラッグ化の実装にも触らない。
- **対価**: タグの付け方に制約が増える。英数字を含まないタグと、既存のタグと同じスラッグになるタグは書けない。違反が分かるのは書いている最中ではなく pre-commit と CI。検査はフロントマターを自前で読むため、`tags` の書き方は1行1件のリストに限られる（読めない書き方は黙って通さず落ちる）。スクリプトは Node の型ストリップに依存して `.ts` の変換関数を直接 import する。
- **戻す条件**: タグを URL のセグメントにするのをやめたとき。スラッグ化そのものが不要になるので、検査ごと消す。
