# 抑制の口は `<script>` の `eslint-disable` だけにし、テンプレートに逃げ道を作らない

スタイルの制限に例外が要るときは、宣言を `.vue` の `<style>` に書き、理由を添えた `eslint-disable` を `<script>` に置く。テンプレートと `.css` には抑制の手段を持たせない。制限の文面も、この手順だけを案内する。

`eslint-disable` が効くのは `<script>` より下だけで、テンプレートはその上にある。テンプレートを抑制するには `vue/comment-directive` と `eslint-plugin-vue` のプロセッサが要り、入れると `<!-- eslint-disable -->` の1行で、ルール名も理由も無しにテンプレートの制限が全部消える。

- **検討した案**
  - **`vue/comment-directive` を入れる**: 案内のとおりの手順がそのまま効く。ただし逃げ道は制限ごとに選べず、テンプレートの制限すべてに一度に開く。理由の無い抑制が、理由を添えた抑制と同じ手数で書けるようになる。
  - **文面から逃げ道を消す**: 例外の置き場が無くなる。第三者由来のインラインスタイルを打ち消す用途は現に要る。
  - **例外の置き場を `<style>` に集める（採用）**: 効く手順だけを案内でき、抑制の口は `<script>` の1箇所に残る。例外を書くには宣言をテンプレートから `<style>` に移すことになり、理由を書くより安くはならない。
- **対価**
  - **テンプレートに閉じた例外も `<style>` に移る**: クラス1つの例外でも、セレクタと宣言を起こすことになる。
  - **抑制は行を指せない**: `<script>` に置いた `eslint-disable` は、その下の `<style>` 全体に効く。
  - **文面が手順を持つ**: 抑制の効く範囲が変われば制限の文面も変わる。案内は1つの綴りに集めてあり、直す場所は1つ。
- **戻す条件**: テンプレートに閉じた例外が、`<style>` に移せない形で要るようになったとき。そのときは `vue/comment-directive` を入れ、理由の無い抑制は別の検査で落とす。
