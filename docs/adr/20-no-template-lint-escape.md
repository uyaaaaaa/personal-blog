# ブロックの並びを固定し、抑制の口を `<script>` の `eslint-disable` だけにする

`.vue` のブロックは `<template>` → `<script>` → `<style>` の並びに固定する。スタイルの制限に例外が要るときは、宣言を `<style>` に書き、理由を添えた `eslint-disable` を `<script>` に置く。`eslint-disable` にはルール名と理由を必須にし、これは ESLint ではなく `scripts/` の検査が見る。テンプレートと `.css` には抑制の手段を持たせない。制限の文面も、この手順だけを案内する。

`eslint-disable` が届くのは書いた場所より下だけで、**並びが決まっていないと、何を抑制できるかもファイルごとに変わる。** 並びを固定して初めて、テンプレートが `<script>` の上に、`<style>` が下に来る。そして `eslint-disable` は、自分より下に出る ESLint の指摘を区別なく消す。**並びの検査も同じように消えるので、抑制の書き方を見る検査は ESLint の中に置けない。**テンプレートを抑制するには `vue/comment-directive` と `eslint-plugin-vue` のプロセッサが要り、入れると `<!-- eslint-disable -->` の1行で、ルール名も理由も無しにテンプレートの制限が全部消える。

- **検討した案**
  - **並びを自由なままにする**: `<script>` が先の SFC では `/* eslint-disable */` の1行でテンプレートの制限が全部消え、`<style>` が先の SFC では案内どおりに書いても落ちる。制限が成り立つかがファイルごとに変わり、文面はどちらの並びも正しく案内できない。
  - **`vue/comment-directive` を入れる**: テンプレートにも行単位の抑制が入る。ただし逃げ道は制限ごとに選べず、テンプレートの制限すべてに一度に開く。理由の無い抑制が、理由を添えた抑制と同じ手数で書けるようになる。
  - **並びを固定し、例外の置き場を `<style>` に集める（採用）**: 抑制の届く先が全ファイルで同じになり、効く手順だけを案内できる。例外を書くには宣言をテンプレートから `<style>` に移すことになり、理由を書くより安くはならない。
- **対価**
  - **並びを選べない**: `<script>` を先に読ませたい SFC でも並べ替えることになる。
  - **抑制の検査だけ置き場が違う**: ルール名と理由の有無は `scripts/` が見る。ESLint の指摘と違い、列も `--fix` も無い。
  - **テンプレートに閉じた例外も `<style>` に移る**: クラス1つの例外でも、セレクタと宣言を起こすことになる。
  - **抑制は行を指せない**: `<script>` に置いた `eslint-disable` は、その下の `<style>` 全体に効く。
  - **文面が手順を持つ**: 抑制の効く範囲が変われば制限の文面も変わる。案内は1つの綴りに集めてあり、直す場所は1つ。
- **戻す条件**: テンプレートに閉じた例外が、`<style>` に移せない形で要るようになったとき。そのときは `vue/comment-directive` を入れ、理由の無い抑制は別の検査で落とす。
