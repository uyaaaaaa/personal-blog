# 記事詳細は取得が確定するまで何も出さず、失敗と記事なしを区別する

`useAsyncData` の `status` が確定するまで本文もフォールバックも描画しない。確定後は `error` と `data` の両方を見て、取得失敗（500）と記事なし（404）を別のカードで出す。

- **検討した案**: (1) `data` が無ければ即フォールバック。Cloudflare 上の SSR は `@nuxt/content` のクエリが失敗しうる（記事「Nuxt Content の記事が SSR 時に取得できない問題とその解決策」）。この失敗はクライアントの再取得で復帰するため、確定前に描画すると「一瞬エラー / 404 → 記事」というちらつきになる。(2) `error` を捨てて `data` だけ見る。通信失敗と記事なしが同じ `null` に潰れ、誤った文言と HTTP ステータスを返す。(3) 全画面エラー（`error.vue`）へ送る。読者が続きを選べなくなるため、記事詳細ではページ内カードにした。
- **対価**: 確定までの間、本文の場所が空白になる。状態の分岐がページ側に増える。
- **戻す条件**: Cloudflare 上の SSR でクエリが失敗しなくなったとき、「確定まで出さない」の部分は不要になる。失敗と記事なしの区別は残す。
