# ブレークポイントは md と lg の2つに限り、ESLint で落とす

表示の出し分けは Tailwind の `md:`（768px）と `lg:`（1024px）だけで行う。他の段の variant（`sm:` `xl:` `2xl:` と `max-*:`）、`<style>` の幅のメディアクエリ、`matchMedia` に渡す幅の条件は、この2つ以外の境界を指すと `npm run lint` が落とす。許す境界は Tailwind の `screens` から作るので、段を足すには `screens` ではなくこの検査の側を直すことになる。

**幅の段は、増やすと組み合わせが増える。** 3段目を足すと確かめる幅が 1.5 倍になり、どの段で何を出し分けたかがコンポーネントごとに散る。2段なら、SP と PC の2通りを見れば全部見たことになる。

- **検討した案**
  - **Tailwind の既定どおり5段使う**: 段ごとの最適化はできるが、`sm:` と `md:` のどちらで折るかが毎回の判断になり、コンポーネント間で境界が揃わない。実際 `ArticleFallback.vue` だけが `sm:` で折れていて、他の一覧と1段ずれていた。
  - **文書の規約のまま目で守る**: `docs/DESIGN_GUIDELINE.md` の「守る線」に置いていたが、上記の `sm:` は入ったまま残っていた。目で見る前提の線は、レビューを通っただけ抜ける。
  - **ESLint で落とす（採用）**: クラスの variant と `<style>` の `@media`、`matchMedia` の文字列のいずれもファイル1つで判定でき、ADR 12 と同じ置き場に収まる。
- **対価**
  - **640px 帯と 1280px 帯の作り込みを捨てる**: 大きな画面ほど余白が伸びるだけになる。
  - **同じ値でも `max-md:` を通さない**: 境界の値ではなく variant の名前で見るため、`md:` の裏返しも落ちる。出し分けは常に「広いほうに足す」向きで書くことになる。
  - **`.css` ファイルと、動的に組み立てたものは見ない**: ADR 12 と同じ範囲。クラスの `` `${prefix}:hidden` `` に加え、`min-width:` `max-width:` 以外の綴りで組み立てたメディアクエリ（`` `(width >= ${w}px)` ``）も抜ける。
- **戻す条件**: 3段目が要る画面（横向きのタブレットで別のレイアウトを出す等）が出たとき。そのときは `docs/DESIGN_GUIDELINE.md` ではなく検査側の許す段を増やす。
