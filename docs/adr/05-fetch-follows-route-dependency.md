# route に依らない取得は、それを出すコンポーネントが持つ

取得を呼べる層の線を「そのルートを所有する層だけ」から「route の値で結果が変わる取得だけを `pages/` が持つ」に引き直す。route に依らず中身が決まる取得（全ページ共通の枠が出す一覧、検索の索引、記事を出せないときの最近の記事）は、それを出すコンポーネントが自分で呼ぶ。置かれる場所で中身が変わる部品は、これまで通り props で受け取る。

- **検討した案**
  - **枠の取得を `layouts/default.vue` に上げて props で配る**: `Header.vue` が自分では使わない値を素通しするだけの中継になり、ヘッダーの表示を1つ足すたびに3ファイルを直す。取得の置き場は「全ページ共通の枠」から動かないまま、判断を持たない層が1つ増える。
  - **`components/` からの取得を一律で禁止し、lint で落とす**: 機械で守れる代わりに、route に依らない取得まで呼び出し側へ押し上がり、呼び出し側が複数あるものは同じ問い合わせを各所に書くことになる。線が「取得かどうか」に引かれ、実際に困る「置かれる場所で中身が変わるか」とずれる。
  - **ルートを持たない層は取得してよい、と広げる**: 字面は短いが、カードや棚もルートを持たないため対象に入る。部品が置かれた文脈からデータを渡される性質を失う。
  - **route への依存で線を引く（採用）**: 元の規約が守っていたのは「route を読める層だけが、それを条件にした問い合わせを組み立てる」こと。ルートを持たない枠には初めから当てはまらない。線がディレクトリではなくコード自身の性質に乗るので、ファイルの置き場を変えても判定が動かない。
- **対価**: 取得が `components/` に散る。同じ問い合わせが別のキーで2箇所に生えても lint は落ちず、payload に同じ内容が2本入る形でしか現れない。「route に依存するか」の判定は人が行う。
- **戻す条件**: route に依らない取得が増えて、どこが何を取っているかを実装横断で追わないと分からなくなったとき。そのときは領域ごとに取得を禁止する lint を先に入れ、規約ではなく機械で線を引く。
