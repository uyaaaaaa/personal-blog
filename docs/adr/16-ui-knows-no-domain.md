# `components/` の共有部品は題材を知らないものだけを `ui/` に置く

`components/` を「何を知っているか」で分ける。記事・サイト構造・Markdown 記法・エラー状態のどれかを知るものは、それを知る領域（`article/` `layout/` `content/` `error/`）に置き、4領域は互いに依存しない。props と `composables`/`utils` だけで決まる部品は `ui/` に置き、`ui/` は `components/` の他を import しない。

- **検討した案**: 「複数から使われるもの」を集める置き場（`common/` や `shared/`）。使用箇所の数で決まる基準は、そのファイルが何であるかを言っていないので、どのファイルも拒めない。実際 `common/` には使用1箇所の部品が溜まり、記事のパスを既定値に持つ「共有」ボタンが置かれ、領域間の依存が1本生えていた（[#246](https://github.com/uyaaaaaa/personal-blog/issues/246)）。「知らない」は肯定の条件なので、置いてよいかを毎回判定できる。
- **対価**: 領域をまたいで使いたい部品は、題材を知っている部分を props に追い出してから `ui/` へ出すことになる。既定値で済んでいた呼び出し側が、値を明示するようになる。
- **戻す条件**: `ui/` に出すための props が増えすぎて、呼び出し側が毎回同じ値を並べるようになったとき。そのときは題材ごとのラッパーをその領域に置く。
