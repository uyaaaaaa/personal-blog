# `accent` は状態に加えて数と記号の目印にも使い、状態の合図は色に限らない

アクセントは1色のまま、リンク・現在地・ホバーのような状態に加えて、件数・エラーコード・`#` のような、読み手が探して数える目印にも当てる。逆向きも緩め、状態を示す手段は `accent` に限らない。目印がすでに `accent` を持っている部品では、ホバーの合図を線の濃さ（`border` から `main`）で作る。[DESIGN_GUIDELINE.md](../DESIGN_GUIDELINE.md) の原則 3 が「意味のある状態」に限り、状態は `accent` で示すとも読める形だったのを、ここで両方向に広げる。

**数と記号は、本文より先に拾われる。** タグの件数も 404 のコードもタグ見出しの `#` も、読む対象ではなく当たりを付ける手掛かりで、状態と同じ速さで目に入る必要がある。同じ役を灰で組むと、隣の文字と同じ速さでしか拾えない。

**目印に当てるのは、見比べて選ぶ数だけ。** タグごとの件数は、どれを開くかを決める材料なので `accent`。見出しの横に出る総数は、今開いているものの大きさを言うだけで選ぶ対象ではないので `sub` に置く。同じ画面に両方あるとき、色が付いている側が選べる側になる。

- **検討した案**
  - **目印を `sub` に戻し、ホバーを `accent` に寄せる（原則そのまま）**: 実装は原則より先に外れていて、404 のコード・Hero のラベル・タグ見出しの `#` がすでに `accent` で出ている。原則を守るには、出したばかりの見た目を3箇所まとめて戻すことになる。
  - **目印だけ広げ、状態は `accent` のままにする**: 目印に `accent` が乗った部品では、ホバーでも `accent` が増える。同じ色が目印と状態を同時に運び、どちらの意味かは色では割れない。
  - **両方向に広げる（採用）**: 部品ごとに `accent` が指す対象を1つ選べる。選ばれなかった側の合図は、線の濃さが持つ。
- **対価**
  - **「`accent` = 状態」で読めなくなる**: 目印かどうかの判断が、部品を作るたびに要る。目印と装飾、選ぶ数と総数の境目は文章では決まり切らないので、増えるほど色は薄まる。
  - **ホバーの合図の作り方が部品ごとに割れる**: 色で示すもの（一覧の行、目次、ページ送り）と、線の濃さで示すもの（タグのピル）が混ざる。
- **戻す条件**: `accent` の付いた要素が1画面に増え、目が拾えなくなったとき。そのときは目印側を落として状態だけに戻し、数は等幅と濃さで見せる。
