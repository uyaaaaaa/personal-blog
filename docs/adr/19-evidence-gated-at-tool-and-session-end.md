# 実測の証跡が無いまま進む経路を、ツールの入口とセッションの終わりで塞ぐ

`verify` の証跡の規約を、手順書を読んでいなくても守られる形に移す。証跡の残らない実測とその土台を壊す実行は
PreToolUse で落とし、開いていない PNG と失われる変更はセッションの終わりで差し戻す。
[ADR 18](./18-git-routes-closed-at-tool-entry.md) の「散文ではなく入口で塞ぐ」を、ツールを呼んだ時点では判定できないものまで広げる。

証跡を残したかは、打つ瞬間には分かっても、見たかどうかは終わるまで分からない。
**入口だけで塞ぐと、測りはしたが見ていない・残しはしたが失われる、が素通りする。** ハーネスの `Stop` は、
その最後の一点で判定できる唯一の場所で、しかもエージェント自身の「もう終わってよい」という判断を覆せる。

- **検討した案**
  - **散文のまま `verify` と `measure` に置く**: 現にそう書いてあった「セッションの頭で作り直す」「撮った PNG は必ず開く」は、守ったかどうかを後から確かめる手段が無い。`.verify/` は git 管理外で履歴にも残らない。
  - **入口（PreToolUse）だけで塞ぐ**: 証跡に落としたかは見られるが、PNG を開いたか・push したかは、最後のツール呼び出しの時点では未確定。止める対象が無い。
  - **入口と終わりの両方で塞ぐ（採用）**: 打ち方は入口で、見たか・残したかは終わりで判定する。終わりの判定は差し戻しであって拒否ではなく、直せば次の停止で通る。
- **対価**
  - **終われなくなる危険と引き換えに、止めるのは理由ごとに1回にした**: 直せない状況（remote が無い、PNG が壊れている）で回り続けないため、同じ理由では二度止めない。1回で直さなければ素通りする。
  - **セッションの境目を跨いだ状態を持つ**: 開いた PNG の記録は `.claude/hooks/state.mjs` に置く。ハーネスが `session_id` を渡さなくなれば、開いたかの判定が毎回リセットされる。
  - **ハーネスの綴りに依る**: `Stop` と `SessionStart` の `source`、`agent_id` の有無が変われば、判定の側を直す。
- **戻す条件**: `.verify/` を git 管理に入れ、証跡の有無を PR の差分で見られるようにしたとき。そのときは終わりの判定を畳み、レビューが見る。
