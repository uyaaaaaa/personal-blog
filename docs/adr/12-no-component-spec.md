# コンポーネントの仕様書を持たず、判断の理由だけを残す

props・表示要件・インタラクションを写した文書（旧 `COMPONENT_SPEC.md`）を廃止し、理由だけを残す。

- **検討した案**
  - **仕様書を維持する**: 「実装が正」と宣言した以上、写した文書は遅れたコピーにしかならず、変更のたびに二重更新を強いる。918行まで育った主因だった。
  - **理由をコードのコメントに置く**: コメントを書かない方針（`.claude/rules/comment.md`）と衝突するため採らなかった。
  - **理由だけを集める（採用）**: 当初は `DECISIONS.md` 1本にまとめ、構造に関わる判断が10を超えた時点で `docs/adr/` に1判断1ファイル、画面・機能ごとの制約を `docs/decisions/` に切り出した。
- **対価**: 「あの値はどこで決めたか」を文書で引けない。Git 履歴と実装を読む。
- **戻す条件**: 仕様書を戻す条件は無い。
