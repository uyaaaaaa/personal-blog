# スクロールの購読をアプリ全体で1本にし、非表示のコンポーネントでは止める

`window` への `scroll` / `resize` の購読は `useScrollFrame` だけが持ち、`lg:` で消えているコンポーネントは `useIsDesktop` を `enabled` に渡して読み取りを止める。

- **検討した案**
  - **各コンポーネントが個別に購読する**: 以前はこれで、SP で非表示のデスクトップ用目次が SP 側の目次と同じだけの処理を裏で回していた（Chromium / 390×844 / CPU 6倍スロットル / 23見出しの記事で実測）。
  - **`v-if` で非表示側をアンマウントする**: SSR の HTML が変わり、デスクトップでサイドバーが後から現れるため却下。
  - **購読を1本にし `enabled` で止める（採用）**: 表示の出し分けは Tailwind の `lg:` のまま。
- **対価**: `enabled` で止める効果は実測したが、**1フレームに集約すること自体の効果は測れていない**（Chromium は scroll を1フレーム1回までしか発火しないため、まとめる対象が無い）。集約は「消費者が増えても購読が増えない」ための構造上の選択であって、性能の根拠は無い。また、1つの rAF で全 `read` を続けて呼ぶため、`read` は他の `read` の書き込み結果に依存できない。
- **戻す条件**: スクロールを購読する消費者が1つになったとき（集約する対象が無い）。
