# 検査は変更されたパスで振り分け、記事だけの変更にコードの規約を課さない

commit と CI で回す検査を、記事（`content/`）に効くものとコードに効くものに割る。記事しか変えていない変更では、コードのための検査と件名の規約を課さない。
これにより「件名は日本語の言い切りで1行」（→ [rules/commit.md](../../.claude/rules/commit.md)）には例外ができ、「commit のたびに回すのは lint だけ」は「回す lint を対象で選ぶ」に変わる。

記事に効く検査は落とさない。フロントマターとタグの衝突は、記事を変えていない変更でも回す。どちらもアプリのコードとスキーマを読むので、コードだけの変更でも結果が変わる。

- **検討した案**
  - **全部を常に回す（現状維持）**: 記事1本・誤字1字に約12秒のコードの検査と、12字以上の件名が要る。記事を足すほど効いてくるうえ、記事だけの PR を main に merge すると同じ検査が二度走る。
  - **検査そのものを緩める（件名の下限を下げる、lint を減らす）**: 記事のために緩めた分がコードにも効く。対象で分けていないので、緩めた側を戻す手段が残らない。
  - **変更されたパスで振り分ける（採用）**: 記事に効く検査を残したまま、コードのための検査と件名の規約を、コードを含む変更にだけ課す。判定は1つの検査が持ち、hook の2本が同じ値を見る。
- **対価**: 記事の置き場という境界が、hook と workflow の両方に現れる。workflow は `paths-ignore` をイベントごとに書くので実装を共有できず、置き場を変えると両方が動く（テストで固定している）。`paths-ignore` で skip した workflow を required check にすると、記事だけの PR が「待ち」で止まる。変更されたパスが取れない回（`--amend`）は、作り直す先のコミットを見に行く分岐が要る。
- **戻す条件**: 記事とコードの境界が `content/` の1本で引けなくなったとき。記事の検査がアプリのコードを読まなくなり、記事だけを別の経路で検査できるようになったときも、振り分けではなく経路を分ける。
