# PR を出す条件と見届けは、作成の入口とセッションの終わりで塞ぐ

`pr` の「出す前」の条件を欠いた `create_pull_request` を PreToolUse で落とし、CI が打つものはその場で打って判定する。本文の署名は deny せず引数から落とす。出した PR の番号を PostToolUse で残し、`assign` の「見届ける」を済ませていないセッションを Stop で止める。

守ったかどうかが後から分からない散文は、破っても誰も気付かない。条件を欠いた PR は出た後にしか見えず、見届けを飛ばしたセッションは、誰も見ていない PR を残して静かに終わる。**手順の最後まで行かせるには、途中の入口だけでなく終わりも塞ぐ必要がある。**

- **検討した案**
  - **散文のまま skills に置く**: 現にそう書いてある §1 と §5 は、破っても何も起きない。ハーネスが足す署名の指示と「書かない」規約の衝突も、その回の読みでどちらかを破っていた。
  - **証跡のファイルの有無だけで「CI を通した」を判定する**: 前のセッションの出力とも、落ちた実行のログとも区別が付かない。通したことを測れない。
  - **作成の入口で実際に打ち、終わりで照合する（採用）**: 通ったかどうかは打てば分かる。見届けは、PR 番号と済ませた手段を突き合わせれば、飛ばしたものだけを名指しできる。
- **対価**
  - **PR の作成が待つ**: CI と同じものをローカルでも打つので、作成のたびに数十秒かかる。落ちれば作成そのものが止まる。
  - **Stop を塞ぐと終われなくなりうる**: 起こす手段が無いセッションを閉じ込めないよう、同じ不足では2度目を止めない。1度は必ず名指しするが、抜け道は1つ残る。
  - **署名の綴りを追うことになる**: ハーネスが足す形が変われば、落とす側の判定を直す。送信後にツールが足すぶんは残る。
- **戻す条件**: CI の結果を作成前に引けるようになり、打ち直さずに判定できるとき。または見届けをハーネス側が持つようになったとき。
