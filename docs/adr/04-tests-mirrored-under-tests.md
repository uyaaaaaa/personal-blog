# テストは `tests/` に実装の構成をミラーして置く

`app/utils/date.ts` に対して `tests/app/utils/date.test.ts` を置く。テストからしか使わないヘルパーも `tests/` に入れ、実装のディレクトリにはプロダクトコードだけを並べる。

- **検討した案**: 実装の隣に `*.test.ts` で置く（この ADR が覆した以前の判断）。同じディレクトリを見るだけでテストの有無が分かり、`app/` を走査する検査にテストがそのまま乗った。テストが実装とほぼ同数まで増えて一覧の行数が倍になり、隣に置く利得よりディレクトリを開いたときの読みにくさが上回った。
- **対価**: テストの有無が実装のディレクトリからは分からない。隣に置くだけで付いてきた依存方向・循環の検査と型検査を、走査範囲と include を `tests/` にも広げて買い直す。実装だけを消したときに取り残されるテストは、実装との対応を見る検査で落とす。
- **戻す条件**: 実装とテストを同じ変更で触るたびに2箇所を行き来する負担が、一覧性の利得を上回ったとき。隣に戻し、広げた走査範囲と include を畳む。
