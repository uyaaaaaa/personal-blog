# 記事の識別を文字だけにし、`emoji` / `image` はスキーマに残す

記事を指す UI は、タイトル・日付・タグ・連番の文字だけで作る。サムネイルも絵文字も出さない。frontmatter の `emoji` / `image` は `content.schema.ts` に残す。`image` は記事ページの OGP が読み続け、`emoji` は読み手がいなくなる。[DESIGN_GUIDELINE.md](../DESIGN_GUIDELINE.md) の原則 4 が「サムネイルに依存しない」に留めていたのを、ここで「持たない」に寄せる。

**絵文字は記事の内容と対応していない。** 書き手が1つ選ぶだけなので、並べても隣との違いを作らず、視線だけを引く。読む速さを上げないものは、綺麗になっても採らない。

- **検討した案**
  - **絵文字だけ残してサムネイルを止める**: 画像の読み込みは消えるが、識別の手掛かりが文字と絵の2系統のままで、一覧の行の高さが絵文字に縛られる。
  - **スキーマからも `emoji` / `image` を落とす**: 既存記事 21 本の frontmatter を書き換えることになり、`check-frontmatter.mjs` と OGP の経路も同時に触る。UI の話に閉じない。
  - **UI から出さず、スキーマは残す（採用）**: 変更が表示側に閉じる。書き手は今までどおり書けて、出すかどうかは UI の側だけで決まる。
- **対価**
  - **frontmatter に読み手のいない値が残る**: `emoji` はどこからも読まれなくなるが、記事には書かれ続け、新しい記事でも書ける状態が残る。
  - **一覧が全部同じ見た目になる**: 目印の無い行が縦に並ぶので、位置を覚えて戻る使い方ができない。連番は一覧の中の序数で、1本公開すれば繰り下がり、一覧の種類ごとに別の番号になるので、代わりにはならない。
- **戻す条件**: 記事の種類が増えて、文字だけでは分野の見分けが付かなくなったとき。そのときも絵ではなく、カテゴリのラベルを行に足す側で解く。
